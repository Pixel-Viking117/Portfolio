Collission w/ a GameOver Scene

Mechanics Implemented

  • OnCollissionEnter via Enemy or Objects == GameOver
  • Player Movement
  • Physics based Shooting
  • Game State Management
  • Audio Integration
  • Animation Control

More Detail

OnCollissionEnter( Collider other )

With the OnCollissionEnter method, I was able to detect when the player collides with an enemy or other objects in the game, triggering the GameOver scene.

Player Movement

I implemented player movement using Unity's New Input system, allowing for smooth and responsive controls. This included handling input for moving left and right as well as applying physics for realistic movement.

Physics based Shooting

I created a shooting mechanic where the player can fire projectiles that are affected by physics. This involved instantiating bullet prefabs and applying forces to them to create a dynamic shooting experience.

Game State Management

I basically did a gameover state management system where I used a simple boolean flag to track whether the game is over or not. When the player collides with an enemy, I set this flag to true and trigger the GameOver scene.

Audio Integration

I integrated audio into the game by creating a custom pixel-art laser sound effect that plays when the player shoots. This added an extra layer of immersion and feedback for the player, enhancing the overall gaming experience.

Animation Control

I implemented animation control for the player character, allowing for smooth transitions between different states such as idle, running, and shooting. This was achieved using Unity's Animator component and setting up appropriate animation parameters to trigger the correct animations based on player actions.

Polling System

The polling system allows for efficient memory without Instantiating a GameObject and then gameObject.Destroy(), which creates unnessercery data and load on the system, you can I think do a cooldown where it gets rid of the pooling effect to minimise the data even more
